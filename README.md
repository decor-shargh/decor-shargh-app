# Decor Shargh — V15

نسخه V15 روی پایه V14 ساخته شده و تمرکز آن سرعت، پنل سرپرست اجرا، تاریخچه، مشکلات قرارداد، لاگ دائمی و حضور کاربران است.

## تغییرات اصلی
- Splash و تمام نمایش‌های لوگو از `brand-ui.webp` کم‌حجم استفاده می‌کنند؛ فایل‌های PNG سنگین قدیمی حذف شدند.
- پنل سرپرست اجرا فقط «خانه» و «قراردادها» دارد و بخش «بیشتر»/لاگ کامل Admin در آن نمایش داده نمی‌شود.
- ثبت درصد و «انجام شد» به‌صورت Optimistic انجام می‌شود؛ UI بلافاصله تغییر می‌کند و Firestore با Persistence تغییر را حتی در حالت Offline نگه می‌دارد و پس از اتصال Sync می‌کند.
- رندرهای تکراری بعد از ثبت درصد حذف و بروزرسانی کارت‌ها Debounce شده است.
- تاریخچه قرارداد Cache و قبل از بازشدن به‌صورت مخفی Prewarm می‌شود؛ در حالت باز Real-time است.
- Admin و سرپرست اجرا تاریخچه را می‌بینند؛ فقط Admin واقعی در پنل Admin می‌تواند رکورد یا کل تاریخچه قرارداد را حذف کند.
- بخش «موارد و مشکلات» برای Admin و سرپرست اجرا فعال است؛ وضعیت باز/انجام شد، ویرایش/حذف موارد خود سرپرست، و آخرین مشکل + تعداد مشکلات باز روی کارت قرارداد نمایش داده می‌شود.
- لاگ سیستم دائمی و فارسی در `auditLogs` ذخیره می‌شود و طبق Rules برای هیچ‌کس حتی Admin قابل حذف/ویرایش نیست.
- ایجاد/ویرایش قرارداد، درصد، انجام‌شدن فعالیت، تغییر وضعیت، فعالیت‌ها، مشکلات و تغییر دسترسی کاربران در Audit ثبت می‌شوند.
- بخش «پنل‌ها» در Admin امکان Preview واقعی پنل Admin و سرپرست اجرا را بدون تغییر Role حساب فراهم می‌کند؛ محدودیت‌های ظاهری Preview سرپرست نیز رعایت می‌شوند.
- صفحه کاربران Admin فشرده‌تر شده و وضعیت «آنلاین» یا «آخرین بازدید» را نشان می‌دهد. آنلاین بودن بر اساس فعالیت ۲ دقیقه اخیر و Presence State محاسبه می‌شود.

## نکته انتشار
فایل `firestore.rules` این نسخه باید همراه V15 در Firebase Rules منتشر شود تا قابلیت‌های Presence، تاریخچه، مشکلات، Audit Log و دسترسی محدود سرپرست اجرا درست کار کنند.


## V15.1 hotfix
- اصلاح Firestore Rules برای سازگاری با کاربران قدیمی که فیلد `blocked` ندارند.
- رفع Permission Denied برای Admin بدون تغییر داده‌های کاربران.


## V15.2
- در قرارداد جدید فقط نام مشتری و تاریخ عقد قرارداد اجباری است.
- کد قلم، مبلغ، تاریخ پایان و تاریخ جبرانی اختیاری شدند.
- ورود تاریخ با اعداد پیوسته مثل 14050618 پشتیبانی می‌شود و / خودکار اضافه می‌شود.


## V15.3
- ذخیره قرارداد جدید Local-first/Optimistic شد؛ با یک لمس قرارداد فوراً وارد UI می‌شود و Firestore در پس‌زمینه Sync می‌کند.
- در اتصال کند یا آفلاین، دکمه ذخیره منتظر round-trip سرور نمی‌ماند و چندبار زدن لازم نیست.
- Guard ضد ثبت چندباره و وضعیت «در حال ذخیره...» به فرم اضافه شد.
- قراردادها بر اساس تاریخ پایان از قدیمی‌ترین/عقب‌افتاده‌ترین به جدیدتر مرتب می‌شوند؛ قرارداد بدون تاریخ پایان در انتهای لیست است.
